# پیشرفت، تصحیح و کش — تسک‌های ۵ تا ۷

کاربر باید وارد حساب اپ شده و دوره را به دوره‌های من اضافه کرده باشد. درس‌های داخل سایت به خرید بخش اسپات‌پلیر وابسته نیستند. کاربر از نشست تعیین می‌شود و شناسهٔ مالک از بدنهٔ درخواست گرفته نمی‌شود.

## قراردادهای یادگیری

| مسیر | رفتار |
|---|---|
| مسیر `GET /app/courses/{id}/progress` | پیشرفت درس‌های منتشرشدهٔ داخل سایت و شناسهٔ چالش‌های تکمیل‌شده |
| مسیرهای `GET/PUT /app/lessons/{id}/progress` | مرحلهٔ صفر تا چهار و موقعیت اختیاری ویدئو برحسب ثانیه |
| مسیرهای `GET/PUT /app/lessons/{id}/drafts/{guided|explore}` | ذخیرهٔ مستقل کد دو حالت |
| مسیرهای `GET/PUT /app/project-templates/{id}/workspace` | فایل‌های متنی پروژه، فایل فعال، مرحله و نسخهٔ قالب مبنا |
| مسیر `POST /app/lessons/{id}/complete` | تکمیل درس بدون آزمون، با نسخهٔ فعلی محتوا |
| مسیرهای `POST /app/{lessons|challenges}/{id}/attempts` | تصحیح سروری و ثبت تلاش |
| مسیر `GET /app/quiz-attempts?page=1` | تاریخچهٔ مالک، هر صفحه بیست تلاش |

نسخهٔ صفر در ذخیره به معنی ایجاد اولین رکورد است. ذخیره‌های بعدی نسخهٔ دریافتی را می‌فرستند؛ تعارض با پاسخ ۴۰۹ برمی‌گردد. ارسال مجدد همان داده رکورد اضافی ایجاد نمی‌کند. تکمیل از مرحلهٔ ادامه مستقل است و ارسال مرحلهٔ چهار، قبولی ایجاد نمی‌کند. پروژهٔ ذخیره‌شده با ویرایش قالب بازنویسی نمی‌شود؛ دو نسخهٔ مبنا و فعلی قالب در پاسخ مشخص‌اند.

برای نمونه، ارسال آزمون یک درس به شکل زیر است. شناسهٔ سؤال درس مقدار ثابت `lesson` و شناسهٔ گزینه، اندیس صفرمبنای آرایهٔ گزینه‌ها به شکل رشته است. چالش از شناسه‌های واقعی سؤال و گزینه استفاده می‌کند.

```json
{
  "contentVersion": 1,
  "idempotencyKey": "a-client-generated-unique-request-id",
  "answers": [{ "questionId": "lesson", "optionId": "1" }]
}
```

قبولی درس با پاسخ صحیح و قبولی چالش با پاسخ صحیح به همهٔ پرسش‌ها ثبت می‌شود. گزینهٔ نامعتبر یا پاسخ ناقص خطای ۴۰۰ است. سؤال تغییرکرده خطای ۴۰۹ می‌دهد. تکرار کلید یک درخواست همان نتیجهٔ ثبت‌شده را برمی‌گرداند؛ تغییر پاسخ با همان کلید خطای ۴۰۹ است. قبولی و تلاش درس در یک دستور اتمیک ذخیره می‌شوند. تغییر سؤال و تلاش ناموفق بعدی، تکمیل معتبر قبلی را حذف نمی‌کنند. خروجی محتوا فاقد جواب صحیح است؛ توضیحات پس از تصحیح فقط برای مالک برمی‌گردند.

حد پیش‌فرض هر کد ۲۵۶ کیلوبایت و هر پروژهٔ متنی یک مگابایت و صد فایل است؛ تنظیمات با پیشوند `BITRO_LEARNING_` قابل تغییرند. مسیر فایل باید نسبی، معتبر و یکتا باشد. هیچ‌کدام از این محدودیت‌ها برای حجم ویدئو نیستند. اجرای کد یا کامپایل به این مرحله اضافه نشده است.

## کش و اختلال

زنجیرهٔ خواندن شامل حافظهٔ محلی، ردیس اختصاصی محتوا و دیتابیس است. مقدارهای اولیهٔ انقضا ۱۵ و ۶۰ ثانیه‌اند. ردیس سرویس `backend-cache` با رمز مستقل، سقف ۱۲۸ مگابایت و سیاست `allkeys-lru` اجرا می‌شود. ردیس ورود، رمز و سیاست `noeviction` خودش را حفظ می‌کند. دادهٔ کش قابل بازسازی است و حجم ماندگار ندارد.

فقط خروجی‌های منتشرشدهٔ قابل‌اشتراک کش می‌شوند. مجوز، نقش، پیشرفت، نتیجهٔ آزمون، پیش‌نویس، اطلاعات پرداخت و نشانی امضاشده کش نمی‌شوند. بررسی انتشار و عضویت درس و تصحیح آزمون از دیتابیس انجام می‌شود. کلید موجودیت شامل شناسه و نسخه است؛ صفحات کاتالوگ با تگ محتوای مشترک باطل می‌شوند. برای سادگی این نسخه، ذخیرهٔ هر نوع محتوا تگ مشترک محتوا را باطل می‌کند؛ شامل تغییر فصل و ترتیب نیز هست.

ابطال دیگر نمونه‌ها فوری نیست. خطای ردیس به‌عنوان نبود مقدار کش رسیدگی می‌شود، نوشتن کش ناموفق عملیات کسب‌وکار را ناموفق نمی‌کند و پس از اختلال وقفهٔ کوتاه پیش از تلاش مجدد اعمال می‌شود. شکست ابطال به انقضای کوتاه متکی است. پاسخ ذخیرهٔ ادمین مستقیماً از مقدار ذخیره‌شده است.

## اجرا و بررسی

```powershell
powershell -ExecutionPolicy Bypass -File backend/scripts/Initialize-LocalEnv.ps1
docker compose --env-file backend/.env up --build -d backend-gateway backend-worker backend-storage-gateway frontend admin
docker compose --env-file backend/.env --profile test run --build --rm backend-tests
node backend/scripts/Sync-FrontendContracts.mjs --check
```

اسکریپت تنظیمات، رمز و اتصال مستقل کش را بدون تغییر رمزهای قبلی اضافه می‌کند. مهاجرت افزایشی است و مقدارهای سازگار برای رکوردهای قدیمی دارد. تست‌های دیتابیس در پایگاه‌های جدا اجرا می‌شوند. آزمون رسانه به‌صورت پیش‌فرض کنار گذاشته می‌شود و با اسکریپت معرفی‌شده در راهنمای دوره قابل اجراست.

رابط‌ها همچنان ارائه‌دهندهٔ محلی دارند. ذخیرهٔ حساب نمایشی، بارگیری نسخهٔ ذخیره‌شده، خطای ارتباط، تعارض، سؤال تغییرکرده و تکمیل درس ویدئویی بدون آزمون قابل مشاهده‌اند. بافر کد و پروژه در مرورگر برای هر حساب جداست؛ خطای ذخیره بافر را پاک نمی‌کند. انتقال دادهٔ قدیمی و اتصال واقعی فرانت‌ها به سرور، مربوط به تسک‌های بعدی است.
